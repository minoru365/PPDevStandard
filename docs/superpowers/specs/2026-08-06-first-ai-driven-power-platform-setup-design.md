# 初めての AI 駆動 Power Platform 開発の導線

## 目的

Canvas アプリを手作業で少し扱った経験はあるが、AI 駆動開発は初めて、という開発者が対象である。PPDevStandard を使って、Power Platform 開発で繰り返し必要になるローカル環境とリポジトリ設定を安全にそろえられるようにする。

利用者が次の二つを区別できることを成功条件とする。

- **一度だけ行うこと**: PC と利用する AI クライアントに対する導入・認証・確認。
- **リポジトリごとに行うこと**: そのプロジェクトの正本、対象環境、検証方法を AI に伝え、必要な共通設定をプレビューして適用すること。

## 対象範囲

README を「最初に何をするか」を決める短い入口にする。`initialize-project.ps1` が個別リポジトリへコピーする `docs/AI_DEVELOPMENT_TOOLING.md` を、日常運用まで含む実践ガイドにする。

この変更はドキュメントとテンプレートだけを対象とし、Power Platform 環境、認証、MCP 接続、スクリプトの動作、依存関係は変更しない。

## 情報設計

### README: セットアップの入口

1. このリポジトリが解決する問題と、対象読者を短く説明する。
2. 「一度だけ」と「リポジトリごと」のチェックリストを先に置く。
3. 初期化コマンドの直前に、利用者が置き換える `TargetPath`、`Client`、`Capability` と、書込みを有効にする `Apply` を説明する。
4. まずプレビューし、結果を確認してから `-Apply` を付ける二段階の実行例を置く。
5. 生成される実践ガイドへ案内する。

### AI_DEVELOPMENT_TOOLING.md: 個別リポジトリで読む実践ガイド

1. 最初に、AI は正本や本番環境を自動的に理解しないことを説明する。
2. 「一度だけ」「リポジトリごと」「作業のたび」を順番に説明する。
3. クライアント別に、グローバル指示とリポジトリ指示の役割、置き場所、適用・確認方法を示す。
4. 共通の `AGENTS.md` をプロジェクトルールの正本とし、Codex、Claude Code、GitHub Copilot CLI が利用できるようにする。
5. クライアント固有の指示ファイルは、共通ルールを重複してコピーせず、固有設定・利用方法だけを記す。
6. 開始時の調査、変更、検証、レビューの順と、開発環境／本番環境の境界を明示する。

## 指示ファイルの方針

| 範囲 | 正本 | 用途 |
| --- | --- | --- |
| 個人・全リポジトリ | 各クライアントのグローバル指示 | 承認の好み、普段使うシェル、秘密情報を共有しないなど、個人の作業原則 |
| リポジトリ全体 | `AGENTS.md` | 正本の場所、開発環境の境界、検証コマンド、変更・公開の承認条件 |
| 必要なクライアントだけ | `.github/copilot-instructions.md`、`CLAUDE.md` など | クライアント固有の補足。共通ルールの二重管理はしない |
| 特定の領域 | 入れ子の `AGENTS.md`、Claude の `.claude/rules/`、Copilot の path-specific instructions | その領域だけに必要な制約 |

Codex はグローバルとリポジトリの `AGENTS.md` を階層的に読む。Claude Code は `CLAUDE.md` と `.claude/rules/` を使う。GitHub Copilot CLI は `AGENTS.md`、`CLAUDE.md`、`.github/copilot-instructions.md`、ユーザー指示を組み合わせる。複数クライアントを使う場合は、共通の安全・正本ルールを `AGENTS.md` に一度だけ書く。

## サンプルの基準

サンプルはコピーしてからプロジェクト固有の値を埋められる最小構成にする。次の内容は例ではなく、利用者が必ず置き換える値として明記する。

- リポジトリの正本（Solution、YAML、Canvas 成果物など）の場所
- 開発環境の名前または識別方法。ただし URL・アカウント・トークンは記載しない
- 実行する検証コマンド
- 変更・公開・削除に必要な承認

## 受け入れ基準と確認

- README だけを読んで、初回利用者が「一度だけ」と「リポジトリごと」の作業を区別できる。
- 各コマンド例で、変更する引数と変えない引数が分かる。
- 生成対象のガイドが、Codex、Claude Code、GitHub Copilot CLI の指示ファイルを混同せずに説明する。
- サンプルは秘密情報や特定テナントの値を含まない。
- `initialize-project.ps1` の既存のコピー対象と説明内容が矛盾しない。
- `git diff --check` と既存の PowerShell 検証を実行する。

## 残る判断

グローバル指示には個人の好みだけを置き、プロジェクト固有の正本・環境・承認ルールは絶対に置かない。チームが Claude Code または Copilot の専用ファイルを必須にする場合は、共通 `AGENTS.md` と同じルールを複製せず、そのクライアントだけに必要な手順を追記する。
